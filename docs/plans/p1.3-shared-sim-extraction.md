# P1.3 — Extract duplicated simulation logic (D2–D8) into `src/shared/sim/`

Phase: Q1 / Phase 1.3 per `docs/ROADMAP.md` ("Extract shared-sim duplication D2-D8").
Inputs: `docs/ARCHITECTURE.md` §5.1 duplication inventory (re-derived against current
code, not trusted from the doc), full reads of `src/server/rooms/GameRoom.js`
(1330 lines), `src/LocalRoom.js` (892 lines), `src/shared/combat.js`,
`src/shared/progression.js`, plus harness study of `test/waves.test.mjs` and
`test/phase4.test.mjs`. All `file:line` citations below were read and spot-checked
in the session that produced this document (HEAD = 763a0ab).

Scope: D2 progression bookkeeping, D3 shop effects, D4 burn DoT, D5 enemy-hit
resolution, D6 room-level projectile loop, D7 pause wall / auto-pick deadline,
D8 match reset. D1 is analyzed for completeness but is a stretch item (ROADMAP
deliverable list says D2–D8). D9–D13 (skill cast, orb pickup, power-ups,
player-damage order, respawn) are explicitly OUT of scope until their documented
drift is reconciled; D14–D15 stay as-is per ARCHITECTURE.md.

Ground rules inherited from the existing shared modules (`combat.js`, 
`progression.js`):

- Pure-ish free functions; no `THREE`, no Colyseus imports. Schema objects are
  consumed duck-typed (`MapSchema`/`ArraySchema` via `.get/.set/.delete/.has/
  .entries/.push/.pop/.splice/.clear`) exactly like `progression.js:97-104`
  already does with `countOwned`.
- Importing `SERVER` from `../server/config.js` is allowed (precedent:
  `progression.js:13`; LocalRoom already evaluates it in the browser).
- All nondeterminism is injected: clock (`now()`), RNG (`rng` or position
  sampler), transport/log hooks (`emit`, `log`, `warn`).
- Construction of schema instances (`new PlayerState/OrbState/PowerUpState/
  EnemyState/ProjectileState`) STAYS in the rooms. Shared sim code mutates
  existing instances only.
- Behavior must be byte-equivalent except where a listed drift is deliberately
  reconciled (two cases, both flagged: burn-tick placement in D4, projectile
  clear on reset in D8).

### D6 — Room-level projectile step/collide/remove loop

| | GameRoom.js | LocalRoom.js |
|---|---|---|
| Current impl | `updateProjectiles` **953–1007** (reverse iterate → `stepProjectile` → `projectileExpired(half)` → splice; owner projectiles hit enemies 969–992 incl. burn handoff; PvP branch 995–1005 hits OTHER living players `osid !== proj.ownerSid` via `damagePlayer(osid, victim, proj.damage, proj.x, proj.z)`) | `_updateProjectiles` **712–760** (same skeleton; enemy branch 724–747; "PvP" branch **751–758** fires when `!proj.ownerIsPlayer` and hits the LOCAL player via `_damagePlayer(me, proj.damage, proj)`) |

remove a projectile in LR). Also GR passes coordinates to `damagePlayer`, LR
passes the projectile object as `source` (765–764 `_damagePlayer(player,
amount, source)` reads `source.x/.z`).

**Decision: PARAMETERIZE** — one loop taking hit-handler callbacks:

```js
/**
 * Step every live projectile: move, expire (TTL/bounds), collide with
 * enemies (via ctx.onHitEnemy) and with other living players (via
 * ctx.onHitPlayer(sid, victim)). Removes projectiles on hit/expiry.

export function stepProjectiles(ctx)
```

Unifying LR's inverted dead-code branch onto the GR rule ("owner projectiles
can hit other players") changes nothing observable with one player and is
asserted in the new unit test so it can never silently flip back.

### Context-object convention (every module)

Each extracted function takes a `ctx` built ONCE per room in `onCreate` /
`constructor`:

```js
// GameRoom adapter (sketch)
this.simCtx = {
  state: this.state,                 // WorldState (schema-owned by the room)
  half: this.half,
  players: this.state.players,
  pendingUntil: this.pendingUntil,   // Map sid -> ms deadline
  pendingQueue: this.pendingQueue,   // Map sid -> number[]
  intermissionBox: { until: 0 },     // mutable holder the wall extends
  now: () => Date.now(),
  emit: (sid, type, data) => this.clients.find(c => c.sessionId === sid)?.send(type, data),
  log:  (event, fields) => this.logEvent(event, fields),
  warn: (event, fields) => this.warnEvent(event, fields),
};
// LocalRoom adapter: now: () => performance.now();
// emit: (_sid, type, data) => this._emitMessage(type, data);  // sid dropped
// log/warn: no-ops (or console.debug behind a flag)
```

DI seams, mandatory: `now()` (never defaulted — mixing `Date.now` and
`performance.now` in one ctx corrupts deadlines); position sampler (`samplePos`)
where randomness exists; `emit`/`log`/`warn` transport hooks; `onHitEnemy`/
`onHitPlayer` callbacks for D6; `checkWinWhilePaused` for D7.

Schema ownership stays with the rooms/schema file: all `new *State(...)`
construction, all message registration (`onMessage`), all ArraySchema push/pop
idioms invoked FROM the shared code operate duck-typed on instances the room
created. No shared module may import `colyseus` or `StateSchema.js` — pinned by
a grep assertion in the new tests (see §3).
